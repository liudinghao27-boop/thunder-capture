# Web UI 设计：执行指挥台重置

> **日期**: 2026-06-26  
> **主题**: Web UI 信息架构与客户经理视角重置  
> **适用阶段**: Web UI 重构前置设计  
> **状态**: 已确认方向，待进入实施计划

---

## 1. 目标

把当前 Web UI 从“功能堆叠展示页”重置为“业务执行指挥台”，让客户经理或一线操盘手在登录后 10 秒内知道三件事：

1. 当前系统卡在什么地方。
2. 下一步应该去哪一个页面。
3. 当前采集、设备、发送有没有风险。

这次重置不追求新增功能，而是优先解决以下问题：

- 首页信息过多，主次不清。
- 页面职责交叉，用户需要在多个页面之间来回找入口。
- 首次引导和首页提示是两套并行逻辑。
- “采集”“发送”“项目配置”“设备准备”等概念命名偏技术，不够业务化。
- 当前界面风格装饰性偏强，不利于高密度运营场景。

---

## 2. 目标用户

### 2.1 主用户：客户经理 / 业务操盘手

核心诉求：

- 今天能不能采。
- 今天能不能发。
- 哪个项目缺线索。
- 哪台设备有问题。
- 发送任务有没有真的跑起来，能不能停下来。

行为特征：

- 高频进入系统。
- 对路径清晰度和状态反馈敏感。
- 不关心技术术语，关心“能否执行”和“哪里异常”。

### 2.2 次用户：首次配置的新用户

核心诉求：

- 先做什么。
- 为什么当前不能执行。
- 配置完项目和设备后如何进入第一次采集和发送。

行为特征：

- 容易在空状态和禁用按钮里迷路。
- 需要一条固定的主路径，而不是同时看到多个并列动作。

---

## 3. 设计原则

### 3.1 首页只做调度，不做深操作

首页负责判断当前卡点和下一步，不承担详细配置、复杂表格和深入排障。

### 3.2 每个页面只承担一种职责

项目、设备、线索、任务、设置分别独立，不再互相抢入口。

### 3.3 只保留一个主 CTA

首页不再并列显示多个同级主按钮。主按钮根据当前卡点动态切换。

### 3.4 视觉从“科技展示”切到“运营控制台”

- 保留深色基底。
- 弱化炫光、霓虹和装饰性渐变。
- 强化状态标签、分组、表格、路径和异常提示。

### 3.5 首次引导并入首页路径

不再依赖独立 onboarding modal。首次使用的引导信息收口到首页主路径和状态文案中。

---

## 4. 方案选择

本轮视觉和布局探索中评估了三个方向：

| 方案 | 描述 | 结论 |
|---|---|---|
| 执行指挥台 | 首页以“当前卡点 + 下一步 + 执行路径”为核心 | **采用** |
| 漏斗工作台 | 首页以库存、转化、漏斗数据为核心 | 可作为后续数据模块补充 |
| 异常控制台 | 首页以异常和排障队列为核心 | 适合大规模矩阵阶段后再强化 |

采用“执行指挥台”的原因：

- 最适合当前产品阶段，兼顾新手和日常操盘。
- 与现有 `overview / devices / jobs` 结构衔接成本最低。
- 后续可以平滑吸收漏斗统计和异常控制能力。

---

## 5. 信息架构

左侧导航重排为：

1. 首页总览
2. 项目中心
3. 设备中心
4. 线索中心
5. 任务中心
6. 系统设置

命名调整原则：

- 用业务语言替代技术语言。
- 页面名直接反映“这里是做什么的”。
- “中心”命名适合后续扩展矩阵、统计、批量动作和侧栏详情。

不再建议使用的页面命名：

- `项目配置`
- `设备准备`
- `Jobs`

这些命名更像局部动作或技术实现，不适合作为长期导航。

---

## 6. 首页总览设计

首页总览是整个系统的“执行指挥台”，由三个层次组成。

### 6.1 顶部主调度卡

展示：

- 当前项目
- 当前卡点
- 一句下一步说明
- 唯一主按钮

示例：

- 当前项目：征兵咨询
- 当前卡点：设备未就绪
- 下一步：先完成 1 台测试机验收，再启动发送
- 主按钮：`去设备接入`

### 6.2 四段执行路径

固定展示：

1. 项目配置
2. 设备接入
3. 采集线索
4. 发送任务

每段仅显示：

- 当前状态
- 关键摘要
- 对应跳转页

用途：

- 让新用户知道完整主链路。
- 让老用户快速定位自己卡在哪一段。

### 6.3 下半区监控模块

保留三个模块：

- 最近任务
- 设备概况
- 风险提醒

其中：

- 最近任务：只看最近一次采集或发送结果。
- 设备概况：只看在线、离线、异常数量。
- 风险提醒：只看库存不足、账号未登录、发送上限、任务取消未落地等异常。

### 6.4 首页删减规则

首页不再承担以下内容：

- 过多统计卡
- 大型线索表格
- 深度任务日志
- 设备详情排障
- 独立 onboarding 弹窗
- 并列的“采集/发送”双主按钮

---

## 7. 首页主 CTA 规则

首页主按钮按照以下顺序判断：

1. 没有项目：`创建项目`
2. 有项目但无 LLM：`去系统设置`
3. 有项目和 LLM 但无设备：`去设备接入`
4. 有设备但无线索：`开始采集`
5. 条件齐全但无任务：`开始发送`
6. 有运行中任务：`查看任务执行`

约束：

- 同一时刻首页只出现一个主 CTA。
- 其他动作退化为辅助链接或四段路径上的次级入口。

---

## 8. 五个主页面职责

### 8.1 首页总览

职责：

- 判断当前卡点
- 提供唯一下一步
- 暴露运行风险

不负责：

- 深度配置
- 长表格浏览
- 深日志查看

### 8.2 项目中心

职责：

- 创建、编辑、复制项目
- 维护关键词、对标账号、采集策略、发送策略
- 显示项目级摘要，如平台、库存、目标设备数、合规模式

建议模块：

- 项目列表
- 项目摘要条
- 项目编辑抽屉或弹窗

不负责：

- 长时间运行监控
- 设备排障

### 8.3 设备中心

职责：

- 连接设备
- 扫描设备
- 设备在线检测
- 单设备验收
- 设备异常定位

建议模块：

- 设备表格
- 批量动作区：扫描、添加、检测
- 单设备执行面板
- 异常筛选：离线、ADB 异常、未登录、缺输入法

不负责：

- 任务复盘
- 项目策略维护

### 8.4 线索中心

职责：

- 查看线索库存
- 按项目、状态、平台、时间筛选
- 查看线索详情
- 失败重发
- 导出线索

建议模块：

- 顶部过滤器
- 线索表格
- 批量动作区
- 详情侧板

字段建议：

- 用户
- 来源平台
- 意向分类
- 评论文本
- 采集时间
- 发送时间
- 发送状态

说明：

- “线索池”可继续作为领域概念使用。
- 页面命名更建议外显为“线索中心”。

### 8.5 任务中心

职责：

- 查看采集任务和发送任务
- 监控运行状态
- 发起取消
- 查看执行日志
- 查看截图证据
- 查看任务复盘

建议模块：

- 任务列表
- 运行中任务高亮区
- 任务详情面板
- 失败摘要
- 复盘视图

原则：

- 停止、取消、验收结果都收口到这里。
- 首页只跳转，不承载这些深操作。

---

## 9. 页面跳转关系

### 9.1 首页跳转原则

首页只负责把用户送到正确页面，不做复杂执行。

### 9.2 典型流转

首次配置流：

`首页总览 -> 项目中心 -> 设备中心 -> 首页总览 -> 采集 -> 任务中心 -> 发送 -> 任务中心`

日常操盘流：

`首页总览 -> 线索中心 / 任务中心 / 设备中心`

异常排障流：

`首页总览 -> 设备中心`  
`首页总览 -> 任务中心`  
`线索中心 -> 任务中心`

### 9.3 关键边界

- 项目中心可以发起采集，但执行详情回任务中心。
- 设备中心可以做验收和修复，但任务态仍回任务中心。
- 线索中心可以做失败重发，但后续进度回任务中心追踪。

---

## 10. 首次使用策略

当前独立 onboarding modal 建议下线，替换为首页路径式引导。

替换方式：

- 首页主调度卡显示“当前卡点 + 下一步”
- 四段执行路径展示完整主链路
- 各段缺失条件显示原因和跳转页

优点：

- 不会出现弹窗说一套、首页又说一套的问题
- 老用户不会被重复打断
- 新用户能在主界面里理解完整操作路径

---

## 11. 视觉建议

### 11.1 保留

- 深色主基底
- 品牌识别色作为主 CTA 和状态强调
- 现有页面的整体框架感

### 11.2 调整

- 减少大面积炫光和装饰性渐变
- 降低悬浮感和“卡片套卡片”的层级
- 使用更稳定的区块分组和行分隔
- 强化表格、标签、数字和状态语义

### 11.3 风格定位

不是营销展示台，而是业务运营控制台。

关键词：

- 稳
- 清楚
- 高密度
- 强状态
- 可执行

---

## 12. 实施范围

### 12.1 本轮包含

- 导航重命名与重排
- 首页总览结构重做
- onboarding 收口到首页
- 五个主页面职责边界清理
- 首页主 CTA 逻辑统一
- 局部文案业务化

### 12.2 本轮不包含

- 全量移动端适配
- 新平台采集能力扩展
- 设计系统全面重建
- 后端任务调度重构
- 视觉品牌全面重做

---

## 13. 验收标准

设计层验收标准：

1. 登录后用户能在 10 秒内看懂当前下一步。
2. 首页不会同时出现多个同级主按钮。
3. 新用户无需依赖弹窗即可走完“项目 -> 设备 -> 采集 -> 发送”。
4. 每个主页面的职责能用一句话说清楚。
5. 停止、取消、日志、复盘统一落在任务中心。
6. 设备连接、检测、验收统一落在设备中心。
7. 当前 UI 视觉重心从装饰转向状态和执行。

---

## 14. 实施建议顺序

建议实施顺序如下：

1. 左侧导航重命名与跳转整理
2. 首页总览重构为执行指挥台
3. 移除独立 onboarding modal，收口到首页
4. 项目中心结构整理
5. 设备中心结构整理
6. 线索中心字段与批量动作整理
7. 任务中心运行态与详情面板整理

这样可以先解决认知和路径问题，再逐页压实细节。
